## ระบบพื้นฐาน

### ราคาค้างหลังปิดเครื่อง: แก้ไข 25 กันยายน 2026

เดิมโปรแกรมไม่ดึงข้อมูลเมื่อพบว่าตลาดปิด ทำให้เปิดเครื่องเช้าแล้วราคาค้างจากก่อนปิดเครื่อง ปัจจุบัน `check`/`view` จะตามเก็บแท่ง 5 นาทีและราคาปิดรายวันของรอบล่าสุดที่ปิดแล้วอย่างน้อย 15 นาที โดยไม่เรียก AI/LINE และไม่สร้างสัญญาณย้อนหลัง
เมื่อครบแล้วจะไม่ดึงซ้ำรอบเดิม; หากผู้ให้บริการยังไม่พร้อม ลองใหม่ห่างอย่างน้อยหนึ่งชั่วโมง สูงสุดสามครั้งต่อหุ้นต่อรอบ โดยนับรวมเพดานเดิม 8 เครดิต/นาที และ 760/วันของโปรแกรม (สำรองจาก 800 ไว้ 40)
รอบตามเก็บครบปกติใช้ไม่เกิน 18 เครดิตสำหรับ 9 หุ้น ถ้ามีประวัติแคชแล้วใช้น้อยลง จำนวนครั้งนี้เพิ่มจากรอบตลาดปกติ แต่ทุกคำขอยังผ่านตัวจำกัดเครดิตร่วม
กราฟระหว่างวันแสดงเวลาไทย ส่วนแท่งรายวันยังยึดวันซื้อขายของตลาดสหรัฐ ไม่ตัดแท่งกลางตลาดตอนเที่ยงคืนไทย และไม่รวม extended hours
ระบบบนเครื่องไม่สามารถตรวจราคา/ส่งเตือนระหว่างที่เครื่องปิดหรือหลับได้ การตามเก็บย้อนหลังไม่ใช่การเฝ้าตลาดย้อนหลัง กราฟพอร์ตใช้แท่งราคาจริงที่ตามเก็บภายหลังได้ เฉพาะหลังวันที่แจ้งจำนวนหุ้นและสมมติว่าจำนวนหุ้นคงที่จนแก้ยอด ไม่สร้างธุรกรรม DCA สมมติ

ผู้ช่วยติดตามพอร์ตระยะยาวสำหรับ META, GOOGL, ETN, NVDA, MSFT, TXN, ASML, AMZN และ V
Python 3.12+ บน Windows และออกแบบให้ย้ายไป Linux ภายหลังได้

สถานะ: MVP ที่ทดสอบแบบออฟไลน์ได้ ตั้งค่าเริ่มต้นเป็น `MOCK_MODE=true`
ราคาทั้งหมดในโหมดนี้เป็นข้อมูลสมมุติ บทอธิบายเป็นแม่แบบภาษาไทยในเครื่อง
ไม่ใช่ราคาปัจจุบัน ไม่ได้เรียก AI ไม่ได้ส่ง LINE และไม่ใช้เครดิต API
มี adapter สำหรับ Twelve Data, Codex ในเครื่อง, OpenAI API (ทางเลือก) และ LINE
ค่อยเชื่อมทีละบริการหลังคุณทดสอบ MOCK ผ่าน ไม่จำเป็นต้องสมัครหรือใส่ key ตอนนี้

ตรวจสอบบน Windows ด้วย Python 3.14.5 โดยปิดการเชื่อมต่อเครือข่ายระหว่าง tests
รวมการสร้างรายงาน ข้อมูลเก่า การไม่เปิดเผย secrets และตัวช่วยตั้งค่า
รัน CLI ตรวจหุ้นและสร้างรายงานสำเร็จ ยืนยันรันซ้ำแล้วไม่มีข้อความซ้ำ
ตรวจ JSON/JavaScript syntax ของรายงานผ่าน แต่ยังไม่ยืนยันหน้าตา/การคลิกจริงในเบราว์เซอร์
เนื่องจากเครื่องมือทดสอบเบราว์เซอร์ไม่อนุญาตการเปิด file URL
ไฟล์ PowerShell ผ่านการตรวจ syntax แต่ยังไม่ได้ลงทะเบียนงานจริง และยังไม่ได้ทดสอบบน Ubuntu

ทดสอบเชื่อม Codex จริงสำเร็จหนึ่งครั้งบนเครื่องนี้ด้วยข้อมูล NVDA สมมุติ ได้คำตอบภาษาไทย
บันทึกใน `data/codex-example.txt` โดยไม่ส่ง LINE และไม่ใช้ OpenAI API key
นี่เป็นผลทดสอบการเชื่อมต่อ ไม่ใช่การรับรองความถูกต้องของคำแนะนำลงทุนหรือการทดสอบราคาจริง

## เปิดกราฟแบบดับเบิลคลิก

### หน้าพอร์ตภาพรวม

หน้าแรกเน้นมูลค่าหุ้นรวม กำไร/ขาดทุนที่ยังไม่ขาย ต้นทุน และการเปลี่ยนแปลงจากปิดวันก่อน
มูลค่า = ผลรวม (จำนวนหุ้น × ราคาล่าสุดที่บันทึก) ส่วนกำไร = มูลค่า − ต้นทุนหุ้นที่ถือ
หน้าเว็บและข้อมูลสำหรับ AI ใช้การคำนวณนี้ร่วมกัน กำไรจากภาพพอร์ตเดิมยังเก็บไว้เป็นข้อมูลอ้างอิง
ราคาปิดแท่ง 5 นาทีที่ใหม่กว่า quote จะถูกใช้พร้อมป้ายชนิดราคาและเวลา ข้อมูลขาด/เก่าจะแสดงสถานะ
ไม่เอามูลค่าบางหุ้นมานับเป็นยอดรวมทั้งพอร์ตเมื่อข้อมูลไม่ครบ

- **พอร์ตที่ติดตาม**: รวมราคาที่บันทึกครบทุกหุ้น ณ เวลาเดียวกัน ตั้งแต่วันที่แจ้งจำนวนหุ้น
  ถือว่าจำนวนหุ้นไม่เปลี่ยนจนกว่าคุณอัปเดตยอด ข้ามรอบที่ข้อมูลไม่ครบ ไม่เติมราคาเอง
  เก็บจุดและต้นทุนใน SQLite แยกตามชุดจำนวนหุ้น/ต้นทุน เพื่อไม่เขียนประวัติเดิมใหม่หลัง DCA
- **จำลองด้วยจำนวนหุ้นปัจจุบัน**: ดูแนวโน้มย้อนหลังด้วยจำนวนหุ้นชุดปัจจุบันคงที่
  ป้ายแสดงชัดเจนว่าไม่ใช่ประวัติการลงทุนจริงหรือผลตอบแทน DCA; ช่วง 1 วันใช้แท่ง 5 นาที
  ช่วงยาวใช้ราคาปิดรายวัน เฉพาะวันที่ข้อมูลครบทั้งพอร์ต ไม่เรียก API เพิ่ม
- กราฟรองรับชี้/แตะ เลื่อนดูจุดด้วยคีย์บอร์ด เลือกช่วงเวลา และเปิดเต็มจอ
- ตารางหุ้นเรียงมูลค่า/กำไร/ชื่อได้ กดชื่อหุ้นเพื่อเปิดกราฟรายตัว
- เปิดหน้าไว้จะโหลดรายงานที่บันทึกใหม่ทุก 5 นาที (ปิดได้) ไม่มีการเรียก AI/ราคาเพิ่มจากหน้าเว็บ
  เครื่องต้องเปิดและงานตั้งเวลาต้องทำงาน จึงมีข้อมูลใหม่ให้อ่าน

**หลัง DCA:** ดับเบิลคลิก `Edit Portfolio.cmd` เพื่อเปิดแบบฟอร์มบน Windows
ใส่จำนวนหุ้นรวมที่ถือ และต้นทุนรวม USD ของหุ้นที่ยังถือจาก Dime ไม่ใช่ราคาต่อหุ้นหรือยอดซื้อเพิ่ม
เมื่อเปลี่ยนจำนวนหุ้นจำเป็นต้องใส่ต้นทุนใหม่ด้วย ก่อนบันทึกจะสำรองไฟล์ข้อมูลเดิมไว้ใน `data/`
และเริ่มช่วงกราฟติดตามสำหรับยอดชุดใหม่ ไม่เชื่อมเส้นข้ามการเพิ่มเงินเป็นกำไร
ทุกครั้งที่ยืนยันยอดรวม ระบบบันทึก `data/portfolio-reconciliation.jsonl` เป็นร่องรอยตรวจสอบว่า
ยอดหุ้นและต้นทุนรวมเปลี่ยนจากอะไรเป็นอะไร โดยไม่เดาราคาที่ซื้อ รายการเติมเงิน FX ค่าธรรมเนียม หรือปันผล
ต้นทุนที่ยังไม่ได้กรอกใช้ค่าประมาณย้อนจากมูลค่าและเปอร์เซ็นต์กำไรเดิม; ตัวเลขจึงอาจต่างจากโบรกเกอร์
ยังไม่รวมเงินสด ปันผล ค่าธรรมเนียม ผลตอบแทนหลัง FX และไม่มีการเชื่อมรายการซื้อขายจาก Dime
Python บน Windows ต้องมี Tkinter (มากับตัวติดตั้งมาตรฐาน) สำหรับแบบฟอร์มนี้
รีวิว AI เก่ายังคงเป็นข้อความ ณ วันที่สร้าง ข้อมูลกำไรใหม่จะถูกใช้ในการวิเคราะห์ครั้งถัดไป

### พอร์ตและแผน DCA ส่วนตัว

เก็บภาพพอร์ตที่ผู้ใช้ยืนยันใน `data/portfolio-profile.json` ซึ่งถูกกันออกจาก Git ด้วยกฎ data/*
รายงานจริงแสดงมูลค่า น้ำหนัก กำไรที่รายงาน และต้นทุนประมาณจากมูลค่า / (1 + กำไร% / 100)
หน้า “ภาพรวมสัดส่วนพอร์ต” แสดงวงกลมตามกลุ่มธุรกิจ และแถบตามธีมการลงทุนที่กำหนดในไฟล์ profile
การแบ่งธีมใช้เพื่อมองการกระจุกตัวเท่านั้น หุ้นอยู่หนึ่งธีมต่อหนึ่งกราฟเพื่อให้รวมเป็น 100% จึงไม่ใช่การบอกว่าธุรกิจไม่มีความเกี่ยวข้องกับธีมอื่น
ภาพนี้ไม่ใช่ยอดสด ไม่ใช่ต้นทุนภาษี และแม้มีจำนวนหุ้นแล้ว ระบบยังไม่ตีมูลค่าใหม่จากราคาตลาดจนกว่าจะเพิ่มการอัปเดตยอดถือครองอย่างมีหลักฐาน
เมื่อเกิดเหตุการณ์ใหม่ AI ได้เฉพาะหุ้นที่เกี่ยวข้อง วันที่ภาพพอร์ต แผน DCA และขอบเขตคำแนะนำ ไม่ส่งประวัติส่วนตัวทั้งหมด
โหมด MOCK ไม่โหลดพอร์ตจริง คำตอบเก่าที่บันทึกไว้ไม่ถูกวิเคราะห์ใหม่ และไม่มีการเรียก AI เพียงเพราะเปิดรายงาน
เหตุผลการถือเป็นสมมติฐานเจ้าของพอร์ต ไม่ใช่ผลวิจัยที่ยืนยันแล้ว

### มูลค่าล่าสุด รีวิวพอร์ต และประกาศบริษัท

เมื่อรายงานมีราคาที่บันทึกไว้ครบทุกหุ้น ระบบคำนวณมูลค่าล่าสุดประมาณจาก จำนวนหุ้น × ราคาล่าสุดที่บันทึก และคำนวณน้ำหนักใหม่ให้
จำนวนหุ้นและยอด DCA ไม่เปลี่ยนเอง ข้อมูลอาจเป็นราคาตลาดปิดหรือข้อมูลเก่าหากยังไม่ได้รันรอบตรวจ จึงอ่านเวลาราคาที่เก่าที่สุดบนหน้าเว็บก่อนใช้ตัวเลข

`news-sync` เป็นงานแยกจากรอบตรวจราคาห้านาที ใช้เฉพาะ /press_releases ของ Twelve Data ซึ่งเป็นประกาศบริษัทที่มี source reference
ระบบคัดเฉพาะหัวข้อผลประกอบการ/guidance, ดีลสำคัญ, ผู้บริหาร, กฎระเบียบ และข้อจำกัดการส่งออกก่อนบันทึก ไม่ใช้ข่าวทั่วไปหรือให้ AI แต่งข่าว
ค่าเริ่มต้นกันการกดซ้ำด้วย NEWS_SYNC_MIN_HOURS=24; จึงไม่ใช้เครดิตข่าวในทุกการตรวจราคา

`review` ใช้เฉพาะราคากับประกาศที่บันทึกไว้แล้ว และสร้างได้หนึ่งครั้งต่อสัปดาห์ ISO week
ถ้า Codex พร้อมและยังไม่ชนเพดาน AI จะสรุปตามแผน DCA เดิม; หากไม่พร้อมหรือถึงเพดานจะใช้แม่แบบในเครื่องที่ติดป้ายชัดเจน
ดับเบิลคลิก `Update Research.cmd` เพื่อทำสองขั้นตอนนี้ด้วยมือและเปิดรายงาน ไม่มี LINE และไม่มีงานตั้งเวลาใน Windows ถูกเปิดโดยคำสั่งนี้
ไฟล์รายงานมีข้อมูลพอร์ตส่วนตัวด้วย อย่าแชร์หากไม่ต้องการเปิดเผย; สำรองไฟล์ profile แยกก่อนแก้ไข

### AI ใช้โควตาเมื่อใด

เปิดรายงาน เปลี่ยนกราฟ ซูม หรือคำนวณตัวชี้วัด ไม่เรียก AI
เมื่อกฎพบเหตุการณ์ใหม่ผ่าน cooldown ระบบรวมเหตุการณ์ของหุ้นนั้น ส่งข้อมูลจำเป็นให้ AI และบันทึกคำตอบ การส่ง LINE ซ้ำใช้คำตอบเดิม
ค่าเริ่มต้น `AI_MAX_CALLS_PER_DAY=9` และ `AI_MAX_CALLS_PER_STOCK_PER_DAY=1` จำกัดการพยายามเรียกอัตโนมัติ ต่อวัน UTC ในฐานข้อมูลนี้ ตั้ง 0 เพื่อปิด AI อัตโนมัติได้
นับแม้เรียกไม่สำเร็จหรือโปรแกรมปิดกลางทาง เพื่อไม่เรียกซ้ำโดยไม่ตั้งใจ เมื่อหมดงบยังแจ้งเตือนด้วยแม่แบบที่ระบุว่าไม่ใช่ AI
นี่ไม่ใช่เพดานโทเคนหรือโควตารวมบัญชี Codex: การใช้งานอื่นในบัญชียังนับตามปกติ ปริมาณขึ้นกับงานและคำตอบ
`Test Codex.cmd` / `test-codex` เป็นการทดสอบด้วยมือ นอกเพดานอัตโนมัตินี้ และใช้โควตาจริง
AI ให้ทางเลือกมีเงื่อนไข สิ่งที่ควรตรวจ/รอ และเหตุที่ควรเปลี่ยนแผน ไม่รู้ข่าวหรืองบล่าสุดเอง และยังระบุสัดส่วนลงทุนไม่ได้เพราะไม่มีข้อมูลพอร์ตครบ

หน้าแรกเป็นภาพรวมหุ้นทั้ง 9 ตัวแบบสว่าง เลือกหุ้นเพื่อเลื่อนลงไปดูรายละเอียด
กด “เปิดเต็มจอ” เพื่อขยายกราฟ (ถ้า browser ไม่อนุญาต Fullscreen API จะขยายเต็มหน้าแทน)

เครื่องมือวัดสองจุดใช้ราคาปิด คำนวณ % และส่วนต่าง ไม่รวมปันผล/ค่าธรรมเนียมและไม่ใช่ผลตอบแทนพอร์ต

### กราฟเดียว เลือกช่วงและขนาดแท่ง

ใช้ “ดูย้อนหลัง” เลือกวัน/สัปดาห์/ครึ่งเดือน/เดือน/ไตรมาส/6 เดือน/1–10 ปี/ทั้งหมด/กำหนดวันที่ และ “หนึ่งแท่ง” เลือก 5/15/30 นาที/ชั่วโมง/วัน/สัปดาห์/เดือน
ช่วงย้อนหลังนับตามปฏิทิน อิงวันล่าสุดที่บันทึก ไม่รับรองว่ามีข้อมูลถึงวันนี้
อัตโนมัติเลือก 5 นาทีสำหรับ 1 วัน, 15 นาทีสำหรับ 1 สัปดาห์, รายสัปดาห์สำหรับ 3/5 ปี, รายเดือนสำหรับ 10 ปี/ทั้งหมด และรายวันสำหรับช่วงอื่น
เลือกขนาดแท่งเองได้ตลอด หากประวัติละเอียดไม่พอจะแจ้งข้อจำกัด ไม่แปลงราคาปิดรายวันเป็นข้อมูลรายนาที
แท่งชั่วโมงรวมจาก 5 นาที เริ่ม 09:30 NY แท่งสุดท้ายอาจสั้นกว่าชั่วโมง; หากตัวอย่างไม่ครบแสดงจุดปิดแทน OHLC
ใช้ OHLC จาก time_series interval=5min โดยตรง ไม่สร้างแท่งจาก quote ทุก 5 นาที
แสดงเฉพาะแท่งที่ปิดแล้วและ regular session ไม่มี pre/post-market ไม่เติมแท่งที่ขาดเอง
เวลาเริ่มแท่งในกราฟเป็น **นิวยอร์ก** ส่วนเวลาที่สร้างรายงานและการ์ดภาพรวมเป็น **ไทย**
ไม่วาด SMA รายวันทับกราฟ 5 นาที; ตัวเลข SMA/RSI รายวันยังอยู่เพื่อดูภาพระยะยาวและมีป้ายแยก
การเลือกวัน/ซูม/เต็มจอใช้ข้อมูลในไฟล์ ไม่เรียก API และไม่ใช่ streaming ต้องโหลดรายงานใหม่หลังรอบตรวจ

ตรวจหุ้นปกติใช้ราคาปิดแท่ง 5 นาทีล่าสุดแทน quote request จึงยังอยู่ประมาณ 711 credits/วันเต็ม:
78 รอบ × 9 time_series 5min + ประวัติรายวัน 9 requests ไม่ใช่เพิ่ม intraday บน quote อีกชุด
วันแรกหรือกรณีแก้ปัญหาอาจมีคำขอเพิ่ม แต่ทุกคำขออยู่ใต้เพดานในเครื่อง 760 ต่อวัน UTC
รอบ 09:30 อาจยังไม่มีแท่งที่ปิด จะข้าม ไม่ใช้ราคาวันก่อนปลอมเป็นราคาปัจจุบัน
ปฏิเสธสัญญาณใหม่ถ้าแท่งไม่ใช่ session วันนี้ เก่าเกิน 20 นาที หรือไม่มีราคาปิด session ก่อนหน้าตรงวัน
ข้อมูลจาก feed/แผนอาจล่าช้าหรือครอบคลุมตลาดเพียงบางส่วน ไม่รับรองราคา consolidated real-time
ดู [Twelve Data US equities](https://support.twelvedata.com/en/articles/9935903-us-equities-market-data)

โหลดแท่งย้อนหลังแยกต่างหากนอกเวลาตลาด (ไม่เรียก AI/LINE ไม่เปลี่ยน quote หรือ cooldown):

## ใช้ Codex ที่ล็อกอินอยู่ในเครื่อง

ตั้ง `ANALYST_MODE=codex` ไว้แล้ว เมื่อเปิดราคาจริงและพบเหตุการณ์ใหม่ Python จะเรียก `codex exec`
ผ่านบัญชี ChatGPT ที่ Codex CLI ล็อกอินไว้ ไม่ต้องใส่ OPENAI_API_KEY หรือคัดลอก token ของ Codex
นี่คือการเรียก Codex เป็นงานสั้นแยกแต่ละครั้ง ไม่ใช่การอ่านข้อความจาก task นี้หรือมีความจำบทสนทนานี้อัตโนมัติ
ยังต้องต่ออินเทอร์เน็ต และใช้สิทธิ์/โควตาบัญชี Codex; ไม่ใช่โมเดลออฟไลน์และไม่รับรองว่าใช้งานได้ไม่จำกัด

`MOCK_MODE=true` ยังปิดการเรียก AI อัตโนมัติ เพื่อคงการทดสอบเดิมให้ไม่ใช้โควตา
หากต้องการทดลอง Codex จริงโดยยังไม่มี API ราคาหุ้น ให้เปิด `Test Codex.cmd` หรือรัน:

```powershell
.\.venv\Scripts\python.exe -m app.main test-codex
```

คำตอบจะบันทึกที่ `data/codex-example.txt` ไม่เข้า outbox และไม่ส่ง LINE
เช็กเฉพาะการล็อกอินโดยไม่สร้างคำตอบ:

```powershell
.\.venv\Scripts\python.exe -m app.main doctor --service codex
```

ไม่ต้องเปิดหน้าต่างแชต Codex ค้างไว้ แต่ต้องมี CLI และรันด้วยบัญชี Windows ที่ล็อกอิน Codex อยู่
ถ้าล็อกอินหมดอายุให้รัน `codex login` ด้วยตัวเอง หากเครื่องหาโปรแกรมไม่พบ ตั้ง CODEX_CLI_PATH
เป็น path ของ codex.exe; ระบบลองหา executable ที่ desktop app ติดตั้งไว้ให้ด้วย
CODEX_MODEL เว้นว่างใช้ค่าเริ่มต้นของ CLI ในการเรียกครั้งนี้ หรือใส่ชื่อ model ที่บัญชีคุณใช้ได้
ตัวเรียกข้าม user config ของ Codex จึงไม่สืบทอด model/plugin/คำสั่งส่วนตัวจาก config.toml
CODEX_TIMEOUT_SECONDS เริ่มต้น 180 วินาที หากล้มเหลวใช้แม่แบบสำรองพร้อมป้ายแจ้ง

ส่งเฉพาะ payload ตัวเลขที่โค้ดคำนวณแล้วผ่าน stdin ใช้ sandbox read-only ปิด shell, browser,
plugins, hooks, memory และเครื่องมือที่ไม่จำเป็น ใช้โฟลเดอร์ชั่วคราวแยกและไม่ส่ง key ราคา/LINE/API ใน environment ของ subprocess
คงที่เก็บ login เดิมให้ CLI จัดการเอง ไม่อ่านหรือคัดลอก auth.json เข้าโปรเจกต์
ไม่โหลดเอกสาร AGENTS ของโปรเจกต์มาปนการวิเคราะห์ และไม่บันทึก session rollout ของการเรียกครั้งนี้
เมื่อย้าย VPS ภายหลังต้องติดตั้งและล็อกอิน Codex บนเครื่องนั้นแยกต่างหาก ไม่ย้าย login อัตโนมัติ

### Google Gemini เป็นทางเลือกในอนาคต

ยังคงใช้ Codex เป็นค่าเริ่มต้นและไม่เรียก Gemini เว้นแต่ตั้ง `ANALYST_MODE=gemini` เองใน `.env`.
ใช้ `Setup Connections.cmd` แล้วเลือกข้อ 5 เพื่อเก็บ key; ขั้นตอนนี้ไม่เปลี่ยนโมเดล เว้นแต่ตอบยืนยัน
ค่าเริ่มต้นใช้ `gemini-3.5-flash-lite` ผ่าน REST API ด้วย `requests` ที่โปรเจกต์มีอยู่แล้ว; โควตา/ราคาแตกต่างตามรุ่นและ tier ให้ตรวจใน Google AI Studio ก่อนใช้จริง
เพราะ Free Tier ไม่ได้หมายความว่าทุกรุ่นฟรีหรือได้โควตาเท่ากัน.

ข้อมูลพอร์ต เหตุผลลงทุน ต้นทุน DCA และข้อมูลส่วนตัวจะไม่ถูกส่งไป Gemini โดยค่าเริ่มต้น (`GEMINI_SHARE_PORTFOLIO_CONTEXT=false`).
หากต้องการให้ Gemini ทำรีวิวพอร์ตด้วย ต้องเปลี่ยนเป็น `true` ด้วยตนเองและเข้าใจเงื่อนไขข้อมูลของ Google ก่อน
Google ระบุว่าเนื้อหาที่ส่งบน Free Tier อาจถูกใช้เพื่อปรับปรุงผลิตภัณฑ์. `store=false` ปิดการเก็บประวัติ interaction
ตาม API แต่ไม่เปลี่ยนเงื่อนไขการใช้ข้อมูลของ Free Tier. เก็บ key ไว้ใน `.env` เท่านั้น ห้ามใส่ใน GitHub.
อ้างอิง [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)

หน้ารายงานมีกราฟราคาปิด 20/50/100 แท่งรายวัน เลือกหุ้นได้ทั้ง 9 ตัว ดู % เปลี่ยนแปลงรายวัน
SMA/RSI สัญญาณที่เข้าเกณฑ์ และเปิดอ่านคำอธิบายย้อนหลังได้
ชี้เมาส์หรือแตะได้กล่องวันที่/ราคา เส้นกากบาทและจุดติดตาม คลิกตรึง/ปลดจุด ใช้ลูกศรซ้ายขวาหรือแถบเลื่อนเลือกวัน
เลือกวันเริ่ม/สิ้นสุด ขยาย/ย่อ ดูทั้งหมด และเปิด/ปิด SMA20/50 ได้ โดยไม่ใช้เครดิตเพิ่ม
เลือกแท่งเทียนรายวันหรือเส้นราคาปิดได้ ชี้แท่งเพื่ออ่านราคาเปิด/สูงสุด/ต่ำสุด/ปิด
ตัวแท่งเขียวหมายถึงปิดสูงกว่าเปิด แดงคือปิดต่ำกว่าเปิด เทาคือเท่ากัน (ไม่ใช่เทียบปิดวันก่อน)
ข้อมูล OHLC มาจาก time_series เดิม จึงไม่เพิ่มคำขอ API; MOCK สร้าง OHLC สมมุติพร้อมป้าย
ฐานข้อมูลเก่าจะเพิ่มคอลัมน์เมื่อรัน check โดยเก็บประวัติเดิมไว้ ส่วน report อ่านฐานเก่าได้โดยไม่แก้ฐาน
หากประวัติมีเพียงราคาปิด จะใช้จุดแทนแท่งพร้อมแจ้ง ไม่เดาราคาเปิด/สูงสุด/ต่ำสุด
ข้อมูลจริงจะมีแท่งเมื่อดึง OHLC สำเร็จ ไม่เติมย้อนหลังจากข้อมูลสมมุติ
กด “อ่านกราฟอย่างไร?” ในรายงานเพื่อดูคำอธิบาย SMA และแท่งเทียนสำหรับผู้เริ่มต้น

## สูตรและความหมายของข้อมูล

- การเปลี่ยนแปลงรายวัน = `(ราคาล่าสุด / ราคาปิดวันก่อน - 1) × 100` ไม่ใช่การเปลี่ยนแปลงจากรอบตรวจ 30 นาทีก่อน
- SMA 20/50 = ค่าเฉลี่ยราคาปิด 20/50 แท่งรายวัน ต้องมีอย่างน้อย 51 แท่งเพื่อตรวจการตัดกันของทั้งสองเส้น
- RSI 14 ใช้ Wilder smoothing: ค่าเฉลี่ยกำไร/ขาดทุนแรกใช้ 14 ช่วงราคา จากนั้น `(ค่าเดิม × 13 + ค่าช่วงใหม่) / 14`
- RSI = `100 - 100 / (1 + average_gain / average_loss)`; เพิ่มอย่างเดียวได้ 100, ลดอย่างเดียวได้ 0, คงที่ทั้งหมดกำหนดเป็น 50
- RSI ต้องการอย่างน้อย 15 ราคาปิด ผลอาจต่างจากเว็บไซต์ที่ใช้ประวัติเริ่มต้นหรือการปรับราคาคนละแบบ
- ส่วนต่างเป้าหมาย = `(ราคา / เป้าหมาย - 1) × 100` เป็นระยะเทียบเป้าหมาย ไม่ใช่กำไรจากต้นทุน

SMA/RSI ใช้แท่งรายวันก่อนวันปัจจุบันในเขตเวลา `America/New_York` เท่านั้น
เพื่อกันแท่งที่ยังไม่ปิด แม้หลังตลาดปิดในวันนั้นก็จะนำแท่งวันนี้มาใช้ในวันถัดไป
ราคาที่ตรวจปกติใช้ราคาปิดแท่ง 5 นาทีที่ปิดแล้ว ไม่ใช่ tick ปัจจุบัน ส่วน indicator ใช้วันปิดล่าสุด
doctor --online --service stock ยังคงตรวจ quote/history โดยตรงเป็นเครื่องมือวินิจฉัย ไม่ใช่เส้นทาง polling ปกติ
เวลาในฐานข้อมูลใช้ UTC; เวลา log ใช้เวลาท้องถิ่นของเครื่อง
Mock จำลองวันจันทร์ถึงศุกร์ ไม่ได้จำลองวันหยุดตลาดจริง

ข้อมูลจริงขอ daily history แบบปรับ stock split แต่ไม่ได้รวมเงินปันผล จึงไม่ใช่ total return

## เหตุการณ์ซ้ำและการลองส่งใหม่

- รหัสเหตุการณ์ประกอบด้วยแหล่งข้อมูล หุ้น ชนิดกฎ และวันที่ข้อมูล
- ราคาขึ้น/ลง/ต่ำกว่าเป้าหมายใช้วันที่ quote; RSI/SMA ใช้วันที่ daily bar
- เหตุการณ์รหัสเดิมไม่ส่งซ้ำแม้ cooldown หมดแล้ว; วันข้อมูลใหม่เป็นเหตุการณ์ใหม่แต่ยังติด cooldown ได้
- threshold เป็นระดับต่อวัน: หากราคาลงลึกขึ้นในวันเดิม กฎเดิมจะไม่ส่งเพิ่มใน MVP
- หาก RSI ยังต่ำในวันข้อมูลถัดไป อาจแจ้งใหม่หลัง cooldown ไม่ได้รอ RSI ฟื้นก่อน
- ความผิดพลาดชั่วคราวเก็บข้อความใน outbox และลองใหม่ครั้งเดียวในรอบตรวจถัดไป
- LINE ใช้ retry key เดิม ข้อความเดิม และผู้รับเดิม เพื่อไม่ส่งซ้ำเมื่อคำขอก่อนหน้าอาจสำเร็จ
- รอส่งนาน 23 ชั่วโมงจะเปลี่ยนเป็น `expired` เพื่อไม่ส่งข่าวเก่าและไม่เสี่ยงพ้นอายุ retry key
- LINE 4xx ที่ไม่ใช่ 429 และไม่ใช่การยืนยัน retry เดิม จะเก็บเป็น `failed` ไม่ลองซ้ำอัตโนมัติ
- `accepted` หมายถึง console พิมพ์สำเร็จหรือ LINE รับคำขอแล้ว ไม่ได้รับรองว่าผู้รับอ่านหรือได้รับข้อความ
- ถ้าเปลี่ยนผู้รับ/ช่องทาง ข้อความค้างเดิมจะไม่ถูกเปลี่ยนปลายทาง ต้องตรวจประวัติด้วยตัวเอง

ไม่มีคำสั่งส่งซ้ำถาวร/ลบประวัติใน MVP หากพบ `failed` หรือ `expired` ให้ดู `show-alerts`
และแก้การเชื่อมต่อก่อน เหตุการณ์วันใหม่จะทำงานต่อได้ ป้องกันการรันซ้อนด้วย OS file lock
ควรมีตัวรันเพียงเครื่องเดียวต่อฐานข้อมูล; ไม่แชร์ SQLite ผ่าน network drive

## เชื่อมบริการจริงภายหลัง

ทำหลัง mock ผ่าน และตรวจสิทธิ์ข้อมูล/ค่าใช้จ่ายในบัญชีของคุณก่อน
ไม่มีการสมัครบริการ ทดสอบ API จริง ตั้งเวลาหรือ deploy ระหว่างสร้าง MVP

1. เลือกผู้ให้บริการราคา: มี `StockProvider` และ adapter ของ Twelve Data เตรียมไว้
   ต้องตรวจสิทธิ์ quote/history, ความหน่วง, quota รายวัน และ listing ก่อนใช้งาน
   รอบแรกของวันใช้ 18 credits (ราคา 9 + ประวัติ 9) รอบถัดไปใช้ราคา 9 credits
   เก็บประวัติรายวันใน SQLite แยกตามหุ้นและวันที่นิวยอร์ก ใช้ซ้ำแม้ปิดโปรแกรม
   ระยะห่างขั้นต่ำ 8 วินาทีและเพดาน 760 credits/วัน UTC ถูกบังคับใช้ข้ามรอบ/ข้าม process
2. ใส่ STOCK_API_KEY ใน `.env` ของเครื่อง แล้วตั้ง `MOCK_MODE=false`
   เริ่มด้วย `ANALYST_MODE=template` และ `NOTIFIER_MODE=console` เพื่อตรวจราคาจริงก่อน
3. ใช้ Codex ในเครื่องผ่าน `ANALYST_MODE=codex` และ ChatGPT login เดิม ไม่ต้องมี OpenAI API key
   หากต้องการ OpenAI API แบบแยกบัญชีภายหลัง จึงเลือก `ANALYST_MODE=openai` และตั้ง key/model
4. สร้าง LINE Official Account/Messaging API ด้วยตัวคุณเอง แล้วตั้งค่า LINE_CHANNEL_ACCESS_TOKEN
   และ LINE_USER_ID ของบัญชีผู้รับตามเอกสาร LINE; LINE_USER_ID ไม่ใช่ชื่อ LINE ID ที่ค้นหาเพื่อน
   เพิ่ม OA เป็นเพื่อนก่อน ส่งเฉพาะขาออกจึงไม่จำเป็นต้องเปิด public port ของโปรเจกต์
   เมื่อพร้อมทดสอบจึงเปลี่ยน `NOTIFIER_MODE=line`

LINE Notify ยุติบริการแล้ว ใช้ LINE Messaging API แทน และตรวจโควตาข้อความตามบัญชีจริง
การตอบคำถามกลับจากแชต LINE ยังไม่อยู่ใน MVP เพราะต้องออกแบบส่วนรับข้อความเพิ่ม

ตัววิเคราะห์ได้รับเฉพาะ symbol, ราคา/วันเวลา/แหล่ง, ตัวชี้วัดที่คำนวณแล้ว และเหตุการณ์
ไม่ส่งรายชื่อทั้งพอร์ต จำนวนหุ้น ต้นทุน เงินสด ประวัติแท่งดิบ หรือ API key ใน prompt
ตัวเลขหลักในข้อความถูกประกอบจากโค้ด ส่วน AI ทำหน้าที่อธิบายและเสนอทางเลือกแบบมีเงื่อนไข
เฉพาะตัวเลือก OpenAI API ใช้ `store=False` ซึ่งไม่ได้หมายถึงรับรองว่าไม่มีการเก็บข้อมูลทุกประเภทของผู้ให้บริการ
ส่วน Codex ใช้นโยบายข้อมูลและโควตาตามบัญชี Codex/ChatGPT ที่ล็อกอิน
ข้อจำกัดสำคัญ: prompt ลดการแต่งข้อมูลได้แต่ไม่รับประกัน AI ถูกต้อง ต้องตรวจทานคำอธิบาย
หาก AI ล้มเหลวจะติดป้ายว่าใช้แม่แบบสำรอง ไม่มีการใช้ AI เลือกหุ้นหรือเปลี่ยน threshold เอง

## หลายพอร์ต เพิ่มหุ้น และแบ่งความสำคัญ

เปิด **Manage Portfolios.cmd** บน Windows เพื่อจัดการโดยไม่พิมพ์คำสั่งและไม่ติดตั้งไลบรารีเพิ่ม ใช้ Tkinter ที่มีอยู่กับ Python เหมือนตัวแก้ยอดเดิม แทนการเพิ่มเว็บบริการจัดการข้อมูลส่วนตัวหรือเปิด public port

1. กด **เพิ่มพอร์ต** แล้วตั้งชื่อ พอร์ตใหม่เริ่มว่าง ไม่คัดลอกจำนวนหุ้นจากพอร์ตเดิมและยังไม่เปิด DCA
2. เลือกพอร์ต กด **เพิ่มหุ้น** กรอก ticker สหรัฐและชื่อบริษัทถ้าต้องการ
   - เว้นจำนวน/ต้นทุนทั้งคู่ = ติดตามราคาอย่างเดียว ไม่รวมยอดเงินหรือกำไร
   - ใส่จำนวนหุ้นรวมและต้นทุนรวม USD จากโบรกเกอร์ทั้งคู่ = หุ้นที่ถือในพอร์ตนี้ ไม่ต้องกรอกราคาตลาด
   - หุ้นที่เคยติดตามอย่างเดียว เปลี่ยนเป็นหุ้นที่ถือได้ด้วย ticker เดิมพร้อมยอดทั้งคู่
   - แก้ยอดเดิมหลัง DCA ด้วย **แก้ยอดหุ้น / ต้นทุน** มีสำรองและตรวจว่าข้อมูลไม่ได้เปลี่ยนระหว่างกรอก
3. เลือกพอร์ตหรือหุ้น แล้วกด **ปรับความสำคัญพอร์ต** หรือ **ปรับความสำคัญหุ้น** ใส่คะแนนแล้วกด **OK** เพื่อบันทึกได้ทันที คะแนนมากจะได้โควตาติดตามมากขึ้น คะแนนนี้ไม่ใช่สัดส่วนเงินลงทุน ดูแผนและตัวนับได้ที่แท็บ **การใช้โควตา** ระบบป้องกันข้อมูลเก่าทับรายการที่เพิ่งแก้จากอีกหน้าต่าง
4. ดูแท็บ **การใช้โควตา**: เปอร์เซ็นต์รวม ความถี่ราคาประมาณ สิทธิ์ AI รายวัน และจำนวน AI ที่เรียกแล้ว การเปิดหรือรีเฟรชหน้าตั้งค่าไม่เรียกบริการภายนอก
5. **ใช้เป็นพอร์ตหลักใน LINE** เปลี่ยนพอร์ตเริ่มต้นที่คุยกับบอต; **แผน DCA พอร์ตนี้** บันทึกยอดบาท/วันที่ 1–28 และแบ่งเท่ากันเฉพาะหุ้นที่ถือในพอร์ตนั้น ใส่ 0 เพื่อปิดเตือน การแก้แผนนี้ไม่เปลี่ยน Auto DCA ที่โบรกเกอร์

หน้าเว็บมีตัวเลือกพอร์ตด้านบน เปลี่ยนแล้วแสดงหุ้น ยอดเงิน กำไร ประวัติกราฟ และ S&P 500 ของพอร์ตนั้น ข้อมูลกราฟทุกพอร์ตสร้างจากราคาที่บันทึกแล้ว ไม่เรียก API ใหม่ การเลือกดูหน้าเว็บไม่เปลี่ยนพอร์ตที่เลือกใน LINE ปุ่มจัดการบนเว็บแสดงวิธีเปิดตัวตั้งค่าบนเครื่อง ไม่ใช่แบบฟอร์มส่งข้อมูลผ่านอินเทอร์เน็ต

คำสั่ง LINE เพิ่มเติม:

- `พอร์ตทั้งหมด` — ดูรายชื่อและพอร์ตที่เลือกอยู่
- `เลือกพอร์ต 2` — สลับด้วยหมายเลข (ใช้ชื่อพอร์ตหรือรหัสพอร์ตได้ด้วย)
- `งบระบบ` หรือ `debug` — ดูงบรวมโดยไม่เรียก AI
- `พอร์ต`, `วันนี้`, `DCA`, `อัปเดต`, `บันทึก …`, `แผนลงทุน` และ `ถาม …` อิงพอร์ตที่เลือก

หุ้นตัวเดียวกันในหลายพอร์ตดึงข้อมูลครั้งเดียว แต่จำนวนหุ้น ต้นทุน แผน DCA กำไร จุดกราฟ ร่างแก้ยอดและสถานะยืนยัน DCA แยกกัน การเตือนราคาส่งครั้งเดียวพร้อมชื่อพอร์ตที่ได้รับผลกระทบ ไม่ส่งข้อความเหตุการณ์เดียวซ้ำทุกพอร์ต สรุปรายวัน/สัปดาห์/เดือนและ DCA แยกพอร์ต แต่ยังใช้ outbox และเพดาน LINE รวมเดิม หากหลายสรุปถึงเวลาพร้อมกันอาจส่งทยอยตามเพดาน

### หลักการแบ่งงบ (ไม่ใช่การจัดสัดส่วนเงินลงทุน)

น้ำหนักเป็นคะแนนสัมพัทธ์บวก เช่น พอร์ต A=70, B=30 หมายถึงความสำคัญ 70% / 30% จากนั้นแบ่งคะแนนของพอร์ตไปยังหุ้นตามน้ำหนักภายในพอร์ต หุ้นซ้ำรับคะแนนรวมจากทุกพอร์ตแล้วใช้ราคาชุดเดียว พอร์ตว่างไม่มีส่วนในงบจนกว่าจะเพิ่มหุ้น

แผนราคาใช้ตลาดเต็มวัน 78 ช่อง ช่องละ 5 นาที กัน `3 × จำนวนหุ้นไม่ซ้ำ + 20` credits สำหรับ history ระหว่างตลาด, history หลังปิดตลาด, intraday ปิดตลาด และส่วนเผื่อ จากที่เหลือแบ่งรอบตามคะแนน หุ้นสำคัญกว่าได้รับรอบมากกว่าเมื่อโควตาเริ่มตึง ทุกหุ้นได้อย่างน้อยหนึ่งรอบตามแผนต่อวัน และมากสุด 78 รอบ ไม่เร่งเกินทุก 5 นาทีแม้เหลืองบ หุ้นเดิม 9 ตัวเท่ากัน: 702 รอบราคา + สำรอง 47 = แผน 749/760; สำรองไม่ใช่คำขอที่จะใช้ให้หมดจริง การ retry/รันเองอาจกินส่วนเผื่อ แต่เพดาน 760 และ 8/min ยังบังคับทุกคำขอ

รอบรายหุ้นกระจายบนช่อง 5 นาที โดยเริ่มตรวจที่ตลาดเปิด วันปิดเร็วใช้จำนวนช่องน้อยลง เครื่องปิดไม่ได้สะสมโควตาเพื่อนำมาเร่งเรียกทีหลัง รันรอบใหญ่/แหล่งข้อมูลช้าอาจทำให้ความถี่จริงต่ำกว่าแผน และข้อมูลที่เก่าก็ยังติดป้ายเก่า ไม่ทำให้ราคาดีเลย์กลายเป็น real-time

AI คุม **จำนวนความพยายามเรียก** จาก `AI_MAX_CALLS_PER_DAY` และเพดานรายหุ้นเดิม ไม่ใช่จำนวนโทเค็นจริงของ subscription เมื่อมีหลายพอร์ตกันอย่างน้อย 2 สิทธิ์จากงบรายวันสำหรับรีวิว ข่าว และคำถาม ส่วนสิทธิ์วิเคราะห์เหตุการณ์หุ้นแบ่งตามน้ำหนักพอร์ตก่อนแล้วตามหุ้น จำกัดรายหุ้นตาม config เดิม หุ้นซ้ำไม่ทำ AI ซ้ำ เงินลงทุนไม่มีการเปลี่ยนเอง ไม่เรียก AI ทุกครั้งที่ตรวจราคา และไม่เรียกเพิ่มเพื่อเผาสิทธิ์ที่เหลือ

สิทธิ์เป็นจำนวนเต็มจึงไม่ตรง 70/30 เป๊ะในแต่ละวัน โดยเฉพาะงบเพียง 9 ครั้ง; หุ้นที่น้ำหนักเท่ากันสลับสิทธิ์ตามวัน UTC และหุ้นที่สิทธิ์ 0 ยังตรวจราคา/กฎและส่งแม่แบบได้ รีวิว/ข่าว/คำถามทุกพอร์ตยังชนเพดานรวมเดียวกัน และการถามเองอาจใช้สิทธิ์ที่เหลือของวันนั้น ความสำคัญสูงไม่ได้เพิ่มเพดานหรือรับรองว่าจะแจ้งทุกความเคลื่อนไหว

### ข้อมูลส่วนตัวและขอบเขต

`data/portfolios.json` เก็บชื่อ/น้ำหนัก/หุ้นและพอร์ตที่เลือก พอร์ตเดิมยังอยู่ที่ `data/portfolio-profile.json` ไม่ย้ายหรือเขียนทับระหว่างเปิดหน้าตั้งค่า พอร์ตใหม่เก็บที่ `data/portfolios/<id>/portfolio-profile.json` พร้อมสำรองและ audit ในโฟลเดอร์นั้น ประวัติราคาใช้ SQLite ร่วม ประวัติกราฟแยกด้วยรหัสพอร์ตและชุดยอดหุ้น ไฟล์ทั้งหมดใต้ data/ รวมหน้าเว็บไม่เข้า Git

รองรับสูงสุด 10 พอร์ต / 100 ticker ไม่ซ้ำในรุ่นนี้ เฉพาะ USD และหุ้นสหรัฐที่ provider รองรับ หุ้นใหม่อาจไม่มีราคาหรือประวัติครบในรอบแรก และ SEC/งบยังรองรับเฉพาะ mapping บริษัทที่มีอยู่เดิม; หุ้นนอก mapping แสดง unsupported ไม่เดาข้อมูลงบ RSS หุ้นใหม่ค้นด้วย ticker และคัดเฉพาะหัวข่าวที่มี ticker ชัดเจน จึงอาจตกหล่นข่าวที่ใช้ชื่อบริษัทแทน ตรวจ coverage ก่อนพึ่งคำแนะนำ AI

เพิ่มหุ้นไม่ปรับยอด DCA หรือสัดส่วนการลงทุนเดิมให้เอง และไม่เชื่อมโบรกเกอร์ ไม่มีการส่งคำสั่งซื้อขาย ฟังก์ชันใหม่จะเริ่มใช้ในตัวตรวจและบอตที่เปิดครั้งถัดไป หลังอัปเดตโค้ดให้รีสตาร์ตเฉพาะ Stock Manager หนึ่งครั้ง; หลังจากนั้นการเพิ่มพอร์ต/หุ้น/น้ำหนักมีผลในรอบตรวจถัดไปโดยไม่ต้องรีสตาร์ตอีก
